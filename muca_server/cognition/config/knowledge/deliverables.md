# Project activities, deliverables and milestones
Type: normative · Version: v1 (2026-10-07) · Source: AUI 2026/27 Lesson 1 (Course Introduction), slides 38–39 and 45–49; AUI syllabus (Programma Dettagliato), p. 4

## Team-based project activities (slide 39)
1. **Understanding** stakeholders' profiles and needs.
2. **Reviewing the state of the art**, to avoid reinventing the wheel: web search plus scientific papers (some are provided by the tutors).
3. **Designing, prototyping (and evaluating)** an interactive application based on "advanced" interaction paradigms.
4. **Documenting** the process followed and the results of the work.
5. **Presenting** the work and demonstrating the prototype.

## Results due at each tutoring (slide 45)
At each tutoring session, specific results must be delivered, defined for each project or project topic:
- user needs and requirements;
- design specifications;
- progressive prototypes (+ evaluation).
Which result is due at which tutoring is in the project schedule.

## Milestones (slides 38 and 46)
- **Demo Madness**: ALL groups give a pitch (and demo) of their project at the beginning of December, in a half-day session. Participation is mandatory. Feedback comes from peers, teacher, tutors and external stakeholders.
- **Final project presentation (+ delivery of the project material)** at the official exam dates. It can be given in any exam session, but the winter session (January–February) is STRONGLY RECOMMENDED; dates are yet to be announced.
- Erasmus and double-degree students: schedule your work so that you can give your presentation BEFORE returning to your home country.

## Mandatory deliverables, to be delivered on the exam date (slide 47)
- **Project documentation** (professional quality required): state of the art; needs and requirements; design, technology; (evaluation: study design and results); technical documentation; documentation about user studies (if performed).
- **Project presentation file** (ppt).
- **Prototype** (with source code).
- **Video pitch file** (max 2 minutes).
- Complementary material, if any (e.g. images, video recordings, data tables…).

The syllabus (p. 4) describes the project deliverables as: the source code of the developed technology, one or more video scenarios, comprehensive design and technology documentation, a user manual, a set of slides for the final 20-minute presentation, and, when applicable, an empirical evaluation report.

## Empirical evaluation (slides 48–49)
- Optional in some projects, mandatory in others.
- It can be done at any development stage: requirements analysis, conceptual design, mockups and prototypes, production, launch and maintenance.
- Empirical evaluation of your project means evaluating it with (relevant representatives of) its stakeholders.
- If performed, the evaluation report is included in the deliverables.
